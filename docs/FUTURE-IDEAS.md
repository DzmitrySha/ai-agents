# Идеи на будущее расширение

Черновик продуктовых/технических идей. **Не контракт** и не обязательный roadmap —
ориентир, чтобы не плодить сущности «потому что так в Cursor».

Текущий канон: [`GUIDE-AGENTS-SKILLS-TOOLS.md`](GUIDE-AGENTS-SKILLS-TOOLS.md),
[`GUIDE-EXTERNAL-API.md`](GUIDE-EXTERNAL-API.md), [`API.md`](API.md).

---

## 1. Что уже есть (базовая модель)

| Сущность | Роль |
|----------|------|
| **Agent** | `system_prompt` + tools + skills + LLM/limits; запуск через `/v1/runs` / MCP |
| **Tool** | действие (builtin / HTTP / `mcp:…`) |
| **Skill** | текст `SKILL.md`; при run **целиком** клеится к system prompt (`compose_prompt`) |

Снаружи уже можно «оркестрировать»: фабрика и клиенты зовут агентов как экспертов
(`POST /v1/runs` + SSE) или через MCP (agent-as-tool). **Внутри** одного run
вложенных агентов пока нет.

---

## 2. Не зеркалить весь каталог Cursor

В Cursor рядом Skills есть Rules, Commands, Hooks, Subagents, Plugins, MCPs.
У ai-agents это **control plane агентов**, не IDE — копировать пункты меню один в один
не стоит.

| Cursor | Смысл | У нас сейчас / вывод |
|--------|--------|----------------------|
| **Rules** | постоянные конвенции (`alwaysApply` / globs) | покрывается `system_prompt` + skills (skills уже always-on для привязанного агента) |
| **Skills** | процедурное знание по задаче | каталог skills — достаточно |
| **Commands** | явный slash/действие пользователя | `POST /v1/runs` / MCP tool / UI-тест; отдельная сущность не нужна, пока нет каталога плейбуков |
| **Hooks** | lifecycle IDE (save, commit, agent stop) | нет IDE; ближе — события run / будущие webhooks платформы |
| **Subagents** | делегирование другому агенту | сейчас только **снаружи**; внутри run — идея §4 |
| **MCPs / Plugins** | внешние tools / расширения | MCP connections + MCP servers + agents уже есть |

### Отдельный каталог Rules — не добавлять

Вторая сущность «rules ≈ markdown как skills» даст дубль CRUD/UI/allowlist/MCP
(`get_skill` уже есть). Сценарий «указать папку проекта → ассистент написал правила
приложения» закрывается:

1. `POST /v1/assist/skill` / AI на `/skills` — черновик SKILL.md;
2. или `POST /v1/skills/import-local`;
3. привязка к агенту в `skills: […]`;
4. жёсткие инварианты — в `system_prompt`.

Если понадобится UX «Rules» — лучше **ярлык/тип skill** (`kind: rule` или тег),
а не новая таблица.

## 3. Ленивые skills (экономия контекста)

**Проблема:** все привязанные SKILL.md всегда попадают в system prompt → расход окна модели.

**Идея:** режим progressive disclosure (как skills в IDE):

1. В промпт на старте — только **оглавление**: `slug` + `description` (+ короткое when-to-use).
2. Builtin/tool `get_skill(slug)` — подтянуть полный текст **по запросу** модели.
3. Allowlist: только skills из `agent.skills` (аналогично MCP `get_skill`).

**Флаг на агенте (черновик API):** `skills_mode: always | on_demand`
(`always` = текущее поведение, без ломки опубликованных агентов).

| Плюсы | Минусы |
|-------|--------|
| меньше токенов на типичный run | +1–2 шага ReAct |
| длинные регламенты не жрут контекст зря | модель может «забыть» подтянуть skill |

**Приоритет:** относительно дешёвый win; логично раньше субагентов.

## 4. Субагенты (агент вызывает агента)

**Цель:** оркестратор внутри ai-agents может делегировать работу другому
**published** агенту, без обязательного участия внешней фабрики.

```text
Оркестратор (агент A)
  └── tool: agent:<slug>  →  дочерний Run B
        └── свой prompt / tools / skills / LLM / limits
```

В редакторе A: в `tools` не только `calculator` / `mcp:…`, но и ссылки
`agent:weather-expert` (только published; предпочтительно `shared` или явный
allowlist владельца).

Отдельный раздел меню «Subagents» не нужен — те же agents + новый тип tool-ссылки.

### Инварианты runtime (обязательно)

| Риск | Защита |
|------|--------|
| Циклы A→B→A | граф вызовов / запрет повторного slug в цепочке |
| Взрыв стоимости | `max_depth` (ориентир 2–3), общий бюджет steps/timeout родителя |
| Каша в SSE | дочерний run = отдельный `run_id`; родителю — `tool.call` / `tool.result` с summary |
| Права | дочерний только из allowlist родителя; не «любой published в тенанте» |
| Отмена | cancel родителя → cancel детей |
| Квота роли `user` | nested runs учитывать в дневной лимит |

UI: дерево «родитель → дети» для отладки.

### MVP (первая версия)

1. Реф `agent:<slug>` в `tools` оркестратора.
2. Tool создаёт child run, ждёт terminal status, возвращает финальный текст (усечённый).
3. Сначала `max_depth=1` (листья не зовут других агентов).
4. Лимиты: `min(parent_remaining, child.limits)`.

Дальше (не в MVP): depth > 1, nested streaming мыслей, общий scratchpad.

### Чего не делать в первой версии

- Произвольный multi-agent граф с общим state.
- Долгое ожидание ребёнка без отдельного `run_id` (ломает timeout/SSE-модель).
- Полный стрим мыслей субагента в ответ родителю — только итог (+ короткий лог).

### Стыковка с фабрикой

Фабрика уже оркестрирует снаружи (`/v1/runs`, гибрид catalog/invoke).
Внутренние субагенты имеют смысл, когда **один опубликованный эксперт** сам дробит
работу (например, «юрист» → цитаты + черновик). Иначе оркестрация дублируется
в двух местах: мозг оставить у фабрики, в ai-agents — плоские эксперты.

---

## 5. Commands / Hooks (низкий приоритет)

| Идея | Когда имеет смысл |
|------|-------------------|
| **Commands** | каталог готовых промптов/плейбуков без полного агента; пока хватает agents + `/v1/assist/*` |
| **Hooks** | свой event-bus: после publish / failed run / webhook наружу — это оркестрация **платформы**, не markdown-каталог |

Не заводить CRUD «по аналогии с Cursor», пока нет конкретной боли.

---

## 6. Предлагаемый порядок

1. **`skills_mode: on_demand`** (+ tool `get_skill` в runtime агента) — экономия контекста.
2. **Субагенты `agent:<slug>`** с `max_depth=1`, лимитами, cancel cascade, деревом runs в UI.
3. Углубление: depth > 1, nested events, webhooks/hooks платформы — по запросу.

Практический фокус до этого: укреплять то, что уже есть (agents + skills + tools + MCP +
гибридный catalog), а не размножать сущности под каждый пункт меню Cursor.
